## Context

The gate every PR passes. Its most important property is that integration tests actually run —
a suite that silently skips in CI is worse than no suite, because it reads as a pass.

Read [testing.md](../../docs/context/testing.md) § *CI*.

## Acceptance criteria

- [x] Runs on PRs and on pushes to `main`
- [x] Lint · typecheck · test with coverage · build. All four must pass
- [x] A **Postgres 17 service container**, with `DATABASE_URL_TEST` set, so integration tests run
      for real
- [x] **CI fails if `DATABASE_URL_TEST` is unset** — the skip that's correct locally is a false
      pass here. `src/test/db.ts` (T003) throws at import time when `!hasTestDatabase && CI`, and
      GitHub sets `CI=true`; this workflow sets `DATABASE_URL_TEST` so the suite runs rather than
      trips that guard
- [x] Coverage thresholds enforced: `src/lib/money/**` 95%, `src/server/services/**` 80% — declared
      in `vitest.config.ts`, applied by `npm test -- --coverage`
- [x] Node version pinned (`node-version: 22`) and matching `infra/Dockerfile`'s `node:22-alpine`
- [x] Dependency caching via `actions/setup-node` `cache: npm`; single job, no redundant install
- [x] `npm run test:ci` locally reproduces CI exactly (same four commands, same order)
